Start with a simple picture

Imagine building a small website to keep track of your groceries. HTML puts the title, shopping items, buttons, and forms on the page. CSS makes them look neat. JavaScript makes the Add Item button work. A server/API could save the list so it is still there when you return tomorrow.

Remember: HTML = what is on the page; CSS = how it looks; JavaScript = what happens when you interact.

Lesson 01

Semantic HTML: Give Each Part a Clear Job

HTML is made of elements, usually written with an opening tag and a closing tag. For example, <p>Hello</p> creates a paragraph. Semantic HTML means choosing tags that describe what the content actually is, instead of using a generic <div> for everything.

Everyday analogy: organizing a house

A kitchen, bedroom, and bathroom all have different jobs. A web page is easier to understand when its sections have names too: <header> for the top, <nav> for navigation, <main> for the important content, and <footer> for the bottom.

Example: a recipe website

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <title>My Recipes</title>
</head>
<body>
  <header><h1>My Recipes</h1></header>
  <nav><a href="#breakfast">Breakfast</a></nav>
  <main>
    <section id="breakfast">
      <h2>Breakfast</h2>
      <article><h3>Pancakes</h3><p>Easy recipe.</p></article>
    </section>
  </main>
  <footer>Made at home</footer>
</body>
</html>

Read the example slowly

<head> holds information about the page, such as its title; it is not the visible page heading. <body> contains what visitors see. <h1> is the main heading, <h2> is a section heading, and <h3> is a heading within that section. <article> is a piece of content that makes sense on its own, like a recipe or blog post.

Why this matters: browsers, screen readers, search engines, and other developers can understand the structure more easily. The browser also builds a tree of these elements called the DOM, which JavaScript can work with later.

Lesson 02

Attributes, IDs, Classes & Custom Data

An attribute is extra information inside an opening HTML tag. Think of the tag as an object and its attributes as labels attached to that object. For example, a link uses href to say where it goes.

<a href="https://example.com">Visit website</a>
<p id="welcome" class="message friendly">Hello!</p>
<button type="button" data-action="add">Add item</button>
AttributePlain-English meaningExample
idOne element's unique name on this pageid="welcome"
classA reusable group name; many elements can share itclass="message"
hrefWhere a link takes youhref="about.html"
nameThe name used when sending a form fieldname="email"
data-*Extra information for JavaScriptdata-action="add"

Everyday analogy: people and teams

An id is like one person's employee number: it identifies one person. A class is like the label “team member”: many people can share it. A data-* attribute is like a sticky note with extra details.

Remember: use unique IDs, reuse classes, and never put passwords or secret keys into HTML attributes. Visitors can inspect them.

Lesson 03

Forms: Let People Enter Information

A form groups input fields so a person can type information and submit it. A <label> tells them what to enter; an <input> is the box; and a <button> submits the form. The input's name is the key used when its value is sent.

Example: search for a book

<form action="/books/search" method="get">
  <label for="book-title">Book title</label>
  <input id="book-title" name="title" required>
  <button type="submit">Search</button>
</form>

What happens when you submit?

1. The browser checks simple rules such as required. 2. With method="get", it usually places the field in the URL, such as /books/search?title=Hobbit. 3. The server can use that information to find matching books. POST generally puts submitted values in the request body and is common for creating or updating information. Neither method replaces HTTPS or server-side validation.

Try it: a shopping-list form

This example runs only in your browser. Nothing is sent or saved to a server.

Everyday analogy: filling out a paper form

HTML validation is like the form telling you “You forgot your name.” The server must still check the information, just as a clerk would verify a submitted form before accepting it.

Lesson 04

Tables: Organize Rows and Columns

Use an HTML table when data naturally belongs in a grid, like a school schedule or a price list. A row goes across; a column goes down. Use <th> for headings and <td> for ordinary cells.

<table>
  <caption>Shopping list</caption>
  <thead>
    <tr><th scope="col">Item</th><th scope="col">Price</th></tr>
  </thead>
  <tbody>
    <tr><th scope="row">Apples</th><td>$3</td></tr>
  </tbody>
</table>
Example grocery budget
ItemEstimated priceIn cart?
Apples$3Yes

How the pieces fit

<table> starts the table. <caption> names it. <thead> contains the header area, <tbody> contains the main rows, and <tr> starts each row. scope="col" means a header describes a column; scope="row" means it describes a row.

Common mistake: do not use tables simply to put two boxes next to each other. CSS Grid or Flexbox is better for page layout.

Lesson 05

HTML + CSS: Content Versus Appearance

HTML says what something is. CSS says what it looks like. A heading is still a heading whether it is blue, red, large, or small. CSS lets you change the design without rewriting the content.

Everyday analogy: furnishing a room

HTML is the room's furniture list: table, chair, lamp. CSS decides where the furniture goes, its colors, and its sizes. JavaScript, which comes next, is like the light switch that makes something happen.

Example: style a shopping-list card

<div class="item-card">Apples — $3</div>

<style>
  .item-card {
    padding: 16px;
    border: 1px solid gray;
    border-radius: 8px;
  }
</style>

The period in .item-card means “find elements with this class.” A selector starting with # finds a specific ID. A selector such as p finds all paragraph elements.

What does responsive mean?

A responsive layout adjusts to screen size. CSS Grid can show three cards across on a laptop and one card per row on a phone. A @media rule lets you apply styles only at certain screen widths.

.cards { display: grid; grid-template-columns: repeat(3, 1fr); gap: 12px; }
@media (max-width: 700px) {
  .cards { grid-template-columns: 1fr; }
}
Lesson 06

HTML + JavaScript: Make the Page Respond

HTML can display a button, but JavaScript is what makes that button do something. The browser turns HTML into a collection of objects called the DOM (Document Object Model). JavaScript can find those objects, listen for clicks, and change their text.

Example: update a number when clicked

<p>Items in cart: <strong id="count">0</strong></p>
<button id="add" type="button">Add one</button>
<script>
  let count = 0;
  document.querySelector('#add').addEventListener('click', () => {
    count = count + 1;
    document.querySelector('#count').textContent = count;
  });
</script>

Breaking down the JavaScript

querySelector('#add') finds the button with the ID add. addEventListener('click', ...) waits for a click. count = count + 1 increases the number. textContent updates what the user sees without reloading the page.

What if the information comes from a server?

JavaScript can use fetch() to request information from an API. An API might return JSON, a common text format for structured data.

async function loadCart() {
  const response = await fetch('/api/cart');
  if (!response.ok) throw new Error('Could not load cart');
  const cart = await response.json();
  document.querySelector('#count').textContent = cart.itemCount;
}

Flow: browser asks API → server finds data → server sends JSON → JavaScript updates HTML. This is an illustration; the training page does not connect to an actual API.

Safety tip

Use textContent for ordinary text, especially when it came from another person. Putting untrusted content into innerHTML can allow malicious HTML or scripts to run.

Lesson 07

Keeping HTML, CSS, and JavaScript Organized

Small experiments can put everything in one HTML file, just like this lesson does. As a project grows, separating files makes it easier to find problems and make changes.

Example: a simple shopping-list website

shopping-list/
├── index.html       # Page content and structure
├── css/
│   └── styles.css   # Colors, spacing, layout
└── js/
    └── app.js       # Clicks, updates, API calls

The HTML file can point to the other files:

<link rel="stylesheet" href="css/styles.css">
<script src="js/app.js" defer></script>

What do these paths mean?

css/styles.css means “open the css folder next to this HTML file, then load styles.css.” ../ means “go up one folder.” A leading / usually starts at the website root. defer tells the browser to wait until the HTML is parsed before running the external script.

Everyday analogy: keeping a desk tidy

HTML, CSS, and JavaScript are like separate folders for documents, photos, and receipts. You could throw everything into one folder, but finding and fixing things becomes harder over time.

Repository note: adding a new lesson HTML file does not automatically make it appear in your encyclopedia navigation. If your repository uses a JavaScript lesson list, that list may also need an entry pointing to the new file.

Lesson 08

Accessibility and Debugging: Make It Usable

Accessibility means designing pages that more people can use, including people navigating by keyboard or using a screen reader. Good HTML often gives you accessible behavior automatically when you use the right elements.

Do thisWhy it helps
Use <button> for actionsKeyboard users can activate it easily
Connect <label> to an inputPeople know what the box is asking for
Use descriptive link names“View recipes” is clearer than “Click here”
Add alt text to meaningful imagesScreen readers can describe the image
Show words as well as colors“Out of stock” is clearer than a red dot alone
Use headings in orderReaders can understand the page outline

When something does not work

Open your browser's Developer Tools (often F12 on Windows). The Elements tab shows the page structure. The Console shows JavaScript errors. The Network tab shows whether files and API requests loaded successfully.

Everyday analogy: checking why a lamp is off

You do not immediately buy a new lamp. You check the switch, bulb, and outlet. Debugging a website is similar: check the HTML element, JavaScript error, and network request to locate the actual problem.

Lesson 09

How HTML Works with C#, Blazor, APIs, and Databases

Even when you build a more advanced application, the browser still needs a page it can display. HTML is that page's basic structure. Other technologies help create the page, process requests, or store information.

TechnologySimple explanationShopping-list example
HTMLDescribes the pageShows items and buttons
CSSStyles the pageColors and spaces the item cards
JavaScriptHandles browser interactionsUpdates the item count
ASP.NET CoreC# framework for web apps and APIsReceives requests to save items

REST APIProvides an HTTP interface to data or actionsReturns the saved shopping list as JSON
SQL Server / OracleStores data on the backendStores item names and quantities
Python / FastAPIAnother way to create a backend APIProvides an item-search endpoint

Follow one request

Person clicks “Show my list”
           ↓
JavaScript or Blazor requests /api/items
           ↓
ASP.NET Core API receives the request
           ↓
API reads saved items from a database
           ↓
API returns JSON
           ↓

What HTML cannot do by itself

HTML alone cannot securely save information to a database, check a password against a server, or run backend C# code. Those jobs belong to server-side software. The browser should not contain database passwords or direct database connection credentials.

Big picture: learning HTML first makes CSS, JavaScript, ASP.NET Core, and Blazor easier to understand because you can recognize what the browser ultimately displays.

Apply It

Practice Project: Build a Shopping List

Create a small shopping-list page

Start with a page heading and a section for groceries. Add a table of items and estimated prices. Include a form with a labeled text field and a button. Use CSS to make the page readable on a phone. Use JavaScript to update an item counter when the button is clicked. Later, you can connect the page to an ASP.NET Core API so the list can be saved.

Suggested order: HTML structure first → CSS appearance → JavaScript interaction → optional API connection.

Completion checklist

  • Use semantic headings and sections.
  • Give each form input a label and name.
  • Display tabular data using proper header cells.
  • Keep CSS and JavaScript responsibilities clear.
  • Update values with textContent, not untrusted HTML.
  • Test on narrow screens and with keyboard navigation.
  • Never put passwords or database connection strings in browser code.
